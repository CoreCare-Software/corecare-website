# Privacy rights and subject access request runbook

This runbook covers access, correction, erasure, restriction, objection, portability and other privacy rights requests. A request can be verbal or written and does not need to mention “SAR” or data protection law.

## Intake and deadline

1. Record the request immediately in the Owner Platform `privacy_requests` register. Preserve the original wording and channel.
2. Send an acknowledgement with the case reference. Calculate one calendar month from receipt. If clarification is genuinely required to identify the information, document when the clock is paused and restarted.
3. Do not charge a fee unless the owner has documented a lawful basis for a manifestly unfounded or excessive request.
4. Use an extension of up to two further months only for a complex request or multiple requests. Tell the person within the first month and explain why.

## Identity and scope

1. Ask only for evidence reasonably needed to be confident the response goes to the correct person. Never request identity documents through the public form or ordinary email.
2. Identify whether CoreCare is controller. If a customer controls the requested product records, notify and assist that customer rather than deciding the request for it.
3. Record products, organisations, accounts, date ranges, names, aliases and contact details that define the search.
4. Issue a tracked task to every relevant product owner. Preserve a search record: systems checked, query terms, dates, reviewer and result count.

## Review and response

1. Collect responsive records in a restricted case area. Use a common, readable and secure export format.
2. Check third-party information, legal privilege, crime/tax, safeguarding, management forecasting and other applicable restrictions. Do not apply an exemption without recording the reason and owner approval.
3. Redact only what is necessary. Keep an unredacted evidence copy under restricted access for the case retention period.
4. Send the response using a secure channel. Include purposes, categories, recipients, retention, source, rights and complaint route where required.
5. Record completion, decision, delivery time, recipient verification and any follow-up. Retain the case record for the published period, not the full duplicate export where it is no longer needed.

## Product action states

Each assigned product task uses: `identified`, `searching`, `review`, `ready`, `completed`, `blocked`. A block must name the missing authority, legal hold, technical issue or customer decision. Product owners must not silently delete or alter audit evidence while a request or dispute is active.
